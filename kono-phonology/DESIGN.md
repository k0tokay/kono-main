# 設計メモ

なぜこの形にしたか．変更するときに壊してはいけない不変条件．

## 1. 単一の真実 — `data/phonology.toml`

**問題.** 同じ音素表が `phonology.tex`（手書きの表）、`phonemes.py`（子音リスト）、
`phono_sys.py`（自然類ツリー）、`kono_ipa.py`（IPA 対応）の 4 箇所にあった．
`ng` が `phonemes.py` にはあって `phono_sys.py` には無い、`kh` の IPA が
tex では `[ç]〜[x]〜[χ]` だが `kono_ipa.py` では `x` 固定、といった食い違いが
実際に発生していた．

**方針.** 定義は TOML に 1 箇所だけ置き、tex の表は `scripts/gen_tex_tables.py`
で生成する．コード側に音素や制約表をハードコードしない．

TOML が持つもの: 素性の宣言 / 自然類の定義（素性式）/ 音素目録（素性・IPA・
異音の幅）/ 音節構造の上限 / ω・ν・κ の結合表 / 重さスケール / 口蓋化規則 /
IPA 変換 / 既知の音素配列制約．

**不変条件.** `Inventory.load()` は宣言されていない素性が音素に付いていたら
例外を投げる（typo で素性が黙って無視されるのを防ぐ）．

## 2. 値型 — `Phoneme` / `Seq` / `Syllable` / `Word`

すべて不変（frozen）．`Seq` は `Sequence[Phoneme]` を実装した普通の列で、
`+` は**素の連結**を意味する（Python の慣習に合わせる）．

`phonology.tex` の形態音韻的な `+`（母音結合）と `⊕`（子音結合）は
列演算ではないので `morphology.py` の関数にし、`Seq.vplus` / `Seq.cplus`
から呼べるようにしてある．`Seq + Seq` が文脈依存の融合を起こすと、
スライスや `sum()` のような素朴な操作が壊れるため．

`Word` は「音素列 + 音節化 + アクセント」．同一性は (音素列, 音節化) で決まる．
`naz.loft` と `na.zloft` は別の `Word`．

---

## 3. 音節化 — 貪欲法ではなく全解列挙

**方針.** 合法な音節化を**すべて列挙**し、スコア関数で最良のものを選ぶ．
MOP は「オンセット総和の最大化、同点なら音節数最小」というスコアとして
表現されている（`mop_score`）．

**理由.** 音節化の原則は今後変わりうる（ソノリティ優先、コーダ最大化、
韻脚構造との相互作用）．貪欲実装だとその都度アルゴリズムを書き直すことに
なるが、スコア関数なら差し替えるだけで済む．語は最長でも 12 音素程度なので
列挙のコストは無視できる（分岐は 1 音節あたり高々 3×2×3）．

**強制境界.** `naz.loft` / `naz|loft` のように `.` または `|` を書くと、
その位置を音節境界に固定する．`phonology.tex` の「意味的・形態的境界が
MOP に優先することがある」に対応する．境界が音素の途中に来たらエラー．

**緩和フォールバック.** 結合表を厳密に守る解が無い場合、表を無視した解を
返し、**どこが表に無いかを `Word.notes` に記録する**（例外にしない）．
語彙と宣言済み制約表の齟齬は握り潰さずに可視化するのが目的．
実際にこれで `stcilkant` の `ω = stc`（S+Q はオンセット表に無い）が
1 件だけ見つかった．

## 4. 重さスケールは差し替え可能 — 2 機構モデル

これがアクセント研究側の中心的な設計判断．

`WeightScale` は「核の長短・コーダ子音・**オンセットの余剰子音**」それぞれの
係数を持つ値オブジェクトで、2 つが組み込まれている:

| スケール | オンセット寄与 | 輪郭調のライセンス |
|---|---|---|
| `rime` | 0（tex 準拠） | ライムのみ |
| `onset_sensitive` | 第2子音以降 +1 | オンセットも算入 |

さらに **重さ（mora）と輪郭調ライセンス（licensing_mora）を別メソッドに
分けてある**．これが「プロミネンス（アクセント位置の決定）はオンセットを
含む重さで、モーラ（F の実現可能性）はライムのみ」という 2 機構モデルを
コードで表現したもの．一言語内でプロセスごとに異なる重さ基準を使うのは
Gordon (2006) が示す通り普通にある．

**この設計が生む判別可能な予測.** `Word.contour_problems(scale)` で
両スケールを比較すると:

```
F だけの違反   [rime] 1 件   [onset_sensitive] 0 件
```

唯一の違反は `kwilwa`（FR、軽音節に F）で、`phonology.tex` でも
「表記上は軽音節に F が現れる例外」と明記されている語．`kwi` は
CC オンセットなので、オンセットを算入すると例外でなくなる．

R を含めると差は 13 → 10 件にしか減らない（残りはすべて語末の軽音節の R）．
これは R が語彙アクセントではなく発話末の境界上昇だという保留仮説と整合する．
だから `check_lexicon.py` は F と R を分けて集計する．

**注意.** これは仮説であって確定事項ではない．TOML の doc にもそう書いてある．
`scripts/gen_stimuli.py` が作る刺激語は、この 2 機構モデルの
`onset` 因子（CC をソノリティ勾配で 6 水準に分けてある）を検定するためのもの．

## 5. DSL — 素性列を 1 つの記法で

パターンは「素性を持つシンボルの列」に対して照合される．シンボルが音素でも
音節でも同じマッチャが動く（`Symbol` プロトコル = `.features` を持つもの）．

**tier の設計.**

- `Word.segment_tier()` … 音素 + 語境界 + 音節境界．各音素には所属音節の
  情報（`role`, `syl_index`, `penult`, `syl_weight`, `accent` …）が注入される
- `Word.syllable_tier()` … 音節をシンボルとする列

そのため `[+cons, role=coda]`（コーダの子音）や
`[weight=heavy, penult=true]`（重い penult）が同じ記法で書ける．

**音節境界の透明性.** `.` は**明示的に書いたときだけ**意味を持つ．
書かなければ読み飛ばされる．これをやらないと `*[C][C][C][C]` が
`suis.kant` の `s.k` をまたげず、「単語内の子音列の長さは3以下」という
制約が実装できない．語境界 `#` は透明にしない（語頭・語末の指定が
無意味になるため）．

**マッチの数え方.** 違反回数は「マッチが始まる位置の個数」（重複を許す）．
Hayes & Wilson (2008) と同じ数え方．音節境界だけを消費する空マッチは
開始位置から除外している．

## 6. 制約評価 — 何を帰無仮説にしているか

音韻規則の候補を markedness 制約 `*P` として書き、確率モデルを
**baseline 分布 q の指数傾斜**として定義する:

    P(w) ∝ q(w) · exp(−Σ wᵢ Cᵢ(w))

`q` が帰無仮説である．ここを明示的に選べるようにしたのが要点で、
「その制約が本物か」は**何と比べるか**で答えが変わる:

| baseline | 保つもの | 何を検出できるか |
|---|---|---|
| `unigram` | 音素頻度・語長分布 | 骨格レベルを含むあらゆる配列制約 |
| `positional` | 語頭/語中/語末で別々の頻度 | 位置効果を除いた配列制約 |
| `cv` | CV 骨格の分布も保つ | 骨格を説明変数から外した「どの子音がどこに」 |

`cv` baseline では母音3連続の期待値が構造的に 0 になるので、
そういう制約は `unigram` で見ないと検出できない．これは仕様であって
バグではないが、間違えやすいので README にも書いてある．

**出力する 3 つの数字.**

- `O/E` … 効果量．1 から離れているほど強い
- `p` … 二項検定．小サンプルでの偶然を排除する
- `dLL` … その制約を足したときの対数尤度の改善．**候補間の比較はこれで行う**
  （O/E は稀なパターンで極端な値を取りやすいので順位付けには向かない）

`Grammar.fit` は MaxEnt（Harmonic Grammar）で重みを同時推定する．
期待値は baseline からのサンプルで近似する（モンテカルロ）．
`weight = "inf"` の制約は hard として扱われ、学習の対象外．

## 7. 統計 — tier の抽象化

「何を記号列とみなすか」だけを差し替えれば、同じ統計（分布・位置別分布・
遷移行列・エントロピー・条件付きエントロピー・相互情報量・PMI・ギャップ）が
どのレベルでも取れる．`Tiers` が射影関数を集めたもの:

音素 / IPA / 自然類 / 調音法 / 調音位置 / ソノリティ / 任意の素性 /
音節 / 音節形 (CVC) / 自然類による音節形 / オンセット形 / コーダ形 /
重さ / モーラ数 / アクセント．

`Tiers.zip_tiers` で 2 つを対にできる（`weight×accent` → `heavy/F` など）．

**なぜ tier を抽象化したか.** 「どのレベルに構造があるか」という問いが
そのまま実験になるため．`report_stats.py --all` は主要 tier の相互情報量を
並べて表示する：

```
          tier    I      redundancy
       phoneme  0.7847      0.1947
 natural_class  0.4097      0.1631
syllable_shape  0.3827      0.1491
        weight  0.2822      0.1568
         place  0.1459      0.0632
```

音素レベルの構造の大半は自然類レベルで説明でき、調音位置にはほとんど
配列的な構造がない（`I=0.15`）—— という読みができる．

## 8. 依存関係

- コア（inventory / seq / syllable / prosody / word / dsl / morphology /
  phonetics / texgen / stimuli）… **標準ライブラリのみ**．
  TOML は 3.11 の `tomllib` → `tomli` → 同梱の `_minitoml`（最小実装）の順に
  フォールバックする．最小実装は `tomllib` との出力一致をテストで担保している
- `constraints` … numpy, scipy
- `stats` … numpy, scipy, pandas
- `corpus` … 標準ライブラリ（`to_frame()` のみ pandas）

コアを軽く保ってあるのは、テストが速いことと、音節化やパターン照合が
数値ライブラリのバージョンに引きずられないため．

## 9. 手順 C / D をこの上に載せるとき

まだ書いていないが、置き場所は決まっている:

**C（音声測定）** … `konophon/acoustics.py`．`parselmouth`（Praat）を
オプション依存にして、`stimuli_blind.tsv` + 音声ファイル →
音節ごとの f0（開始・終了・傾き）と母音長を持つ DataFrame を返す．
`Word` の音節列と時間区間を対応づけるのがインタフェース．

**D（モデル比較）** … `konophon/accent_model.py`．
アクセント位置を予測するモデル（韻脚型 × 方向 × extrametricality ×
重さスケール のパラメータ格子）を列挙し、測定値に対する予測精度で比較する．
`WeightScale` を差し替え可能にしてあるのは、この格子の 1 軸をそのまま
既存の型で回せるようにするため．
