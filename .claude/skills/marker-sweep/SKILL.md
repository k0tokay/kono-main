## 入力
- $0：対象の章ファイル．
- `--dry-run`：棚卸しと処置案の表だけを作り，本文を変えない．

今日: !`date +%F` ／ 対象のマーカー: !`grep -nE '\\(todo|memo|fixme|ques)\{' "${CLAUDE_PROJECT_DIR}/$0" 2>/dev/null | head -60; true`

## 禁止事項
- マーカーを一文に置き換えて終わらせない．それを含む表・節・remark の存在意義まで検討する．
- 文献調査・執筆作業・作者主体（P側，趣味判断）の項目を勝手に閉じない．残す場合は「何が決まれば閉じるか」まで書き直す．
- 採択した箇所の前後と，同じ主題を扱う他章の文を読み直さずに終えない（「未決である」が嘘になる）．
- 辞書JSONを直接編集しない．

## 手順
1. **棚卸し**．マーカーを列挙し，(i) 誤植・既解決，(ii) 単純決定（辞書・実装・定義で検証すれば決まる），(iii) 要議論，に分ける．検証には辞書CLI，音韻実装（`kono-phonology/konophon`），本文の定義を実際に当てる．検算は `verifier` へ委ねてよい．
2. **処置**．(i) は削除または散文化．(ii) は本文に暫定表示（日付付き）で書く．(iii) は設計上の問いにまとめ `/codex-consult` へ一往復投げ，結論を暫定採択して本文へ入れる．
3. **構造の見直し**．他章と重複する表は削る．参照三行だけになった節は前節へ畳む．todo だけの節は消して移植先に todo を置く．
4. **隣接する記述の点検**．置換した箇所の前後と，同じ主題を扱う他章の文を読み直す．
5. **記録**．`detail/discussion/<今日>/marker-sweep-<章名>.md` に処置一覧を表で残す（行，元マーカー，分類，処置，根拠）．
6. **検証**．`/checkpoint`（形式検査→コミット）．辞書側の作業は本文に「辞書が移行対象」と書き，パッチとして別に出す．

## チェックリスト
- [ ] 全マーカーが表に載り，(i)(ii)(iii) のどれかに分類されている．
- [ ] 残したマーカーに「何が決まれば閉じるか」がある．
- [ ] 採択箇所の隣接文と他章の同主題の文を読み直した．
- [ ] 本文に入れた決定に日付と「暫定」がある．
