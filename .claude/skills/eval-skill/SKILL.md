---
name: eval-skill
description: スキルのドライラン評価．新しいスキルや改良したスキルを，過去の類似タスク（日付ログにある実績）で試し，再現性・改善度・副作用を PASS/FAIL で判定する．「スキルを評価して」「ドライランして」「棚卸し」で使う．
argument-hint: <スキル名 | --all> [過去タスクのログパス...]
allowed-tools: Read, Grep, Glob, Write, Bash(ls *), Bash(git log*), Bash(git diff*), Bash(python3 *), Agent
---

## 入力
- $0：評価するスキル名．`--all` なら全スキルの棚卸し（各スキルにつき軽く 1 件）．
- $1 以降：ドライランに使う過去タスクの記録（`detail/discussion/<日付>/…`）．指定がなければ，スキルの主題に合う記録を日付ログから 2 件選ぶ（例：`precision-review` なら過去の `precision-review-*.md` とその作者コメント）．
- 前版との比較が要る場合は `git log -p -- .claude/skills/$0/SKILL.md` で前版を得る．

今日: !`date +%F` ／ スキル一覧: !`ls "${CLAUDE_PROJECT_DIR}/.claude/skills"`

## 禁止事項
- ドライランで本文・辞書・レビューを変更しない．成果物は `.claude/dryrun/` と作業用の一時ファイルだけ．
- 実績（人間が確認した過去の成果）を正解として扱い，スキルの出力が実績と食い違う理由を「実績が間違い」で片付けない．
- 評価を印象で書かない．各軸に，何を入力し，どの手順で何が出て，実績とどこが違ったかを書く．

## 手順
1. `.claude/skills/$0/SKILL.md` を読み，入力・禁止事項・手順・チェックリストを把握する．
2. 過去タスクごとに，別文脈（`Agent` で新しいサブエージェント，モデルは主担当と同じか一段下）にスキル本文と当時の入力だけを渡して実行させる．当時の成果物や作者コメントは渡さない．本文の版は当時の基準コミットに合わせる（`git show <hash>:<path>`）．
3. 出力を実績と比べ，3 軸で判定する：
   - **再現性**：手順どおりに進み，別のタスクでも同じ形の成果物が出たか．手順が読み手によって揺れる箇所を列挙．
   - **改善度**：前版の Problem（`.claude/retro/` の該当項目）が新版で消えているか．前版がなければ「初版」．
   - **副作用**：禁止事項の違反，範囲外の編集，冗長な出力，過剰な確認質問など，新版が持ち込んだ別の問題．
4. `.claude/dryrun/<今日>-$0.md` に書く：対象スキルの版（コミット），使った過去タスク，各軸の PASS/FAIL と根拠，FAIL への改善案（スキル本文の差分として）．
5. FAIL があれば `/improve-skill $0` を勧める．全 PASS なら本番に使ってよい旨を記す．

## チェックリスト
- [ ] ドライランは別文脈で，当時の成果物を見せずに行った．
- [ ] 3 軸それぞれに PASS/FAIL と根拠がある．
- [ ] FAIL の改善案がスキル本文の差分として書かれている．
- [ ] 本文・辞書・レビューに変更がない（`git status` で確認）．
