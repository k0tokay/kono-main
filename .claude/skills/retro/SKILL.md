---
name: retro
description: タスク終了時の振り返り（フィードバック経路「制作→ワークフロー」）．使ったスキルの手順に対して Keep/Problem/Try を書き，Try をスキル改良の候補にする．/production と同じループで，戻し先が本文ではなく手順であるだけ．「振り返って」「レトロ」「今回の反省を残して」で使う．
argument-hint: <使ったスキル名> <主題>
allowed-tools: Read, Grep, Glob, Write, Bash(git log*), Bash(git diff*), Bash(ls *)
---

## 入力
- $0：振り返る対象のスキル名（`.claude/skills/$0/SKILL.md`）．複数なら主なもの．
- $1：主題（対象章や作業名）．
- この会話でのタスクの経過（依頼，中間結果，作者コメント，最終成果）．

今日: !`date +%F` ／ 既存の振り返り: !`ls "${CLAUDE_PROJECT_DIR}/.claude/retro" | tail -5`

## 禁止事項
- 成果物の自賛や一般論を書かない．手順のどの行が効いたか，どの行が守られなかったかを書く．
- Problem を書いて Try を書かないままにしない．Try はスキル本文への具体的な変更（追加する行，削除する行，順序の入れ替え）として書く．
- 理論の内容（採否や本文の是非）をここで裁かない．それは日付ログと本文の仕事．

## 手順
1. `.claude/skills/$0/SKILL.md` を読み，手順・禁止事項・チェックリストを一行ずつ，今回の経過と突き合わせる．
2. **Keep**：機能した手順・禁止事項．次回も残す理由を一行で．
3. **Problem**：守られなかった手順，足りなかった入力（仕様の所在が未記載，前提が推測だった），冗長だった手順，フックが検知できなかった問題．作者コメントで指摘された点を必ず含める．
4. **Try**：Problem ごとに，スキル本文への変更案を一つずつ．禁止事項の再掲位置，手順の順序，チェックリスト項目の追加，フック・スクリプトへの機械化を候補にする．
5. `.claude/retro/<今日>-$0-$1.md` に次の形で書く：`# <スキル> / <主題>`，`## 経過`（3〜5行），`## Keep`，`## Problem`，`## Try`（各項目に対応する Problem 番号）．
6. Try が一つでもあれば `/improve-skill $0` を勧める（自動では実行しない）．

## チェックリスト
- [ ] Keep/Problem/Try が全て手順・禁止事項・チェックリストの行に対応づいている．
- [ ] 作者コメントの指摘が Problem に含まれている．
- [ ] Try がそのままスキル本文の差分に書き換えられる粒度である．
- [ ] ファイル名が `YYYY-MM-DD-<スキル>-<主題>.md` である．
