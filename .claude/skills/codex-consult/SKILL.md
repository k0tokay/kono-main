## 入力
- $0：主題名（ファイル名に使う）．
- $1：問い，または問いを書いたファイル．設計上の問いとして定式化されていること（何を決めれば閉じるか）．
- 現行案と代替案，最小例，制約（新しい形式的装置の禁止，時刻指標の新設禁止など該当するもの）．

今日: !`date +%F`

## 禁止事項
- 同意を求めるプロンプトにしない．診断と処方を両方攻撃させる．
- codex の結論を根拠に採択しない．AI同士の合意は根拠にならない．原典・形式的帰結・具体例・変更の波及で検証する．
- 根の変更（設計規範・骨格木・体系の型）と趣味判断（語形・命名・文体）を採択しない．作者の裁定に回す．
- 三往復以上しない．二往復で決まらなければ作者に問いを返す．

## 手順
1. `detail/discussion/<今日>/$0-codex-prompt.md` を書く．含めるもの：役割（反例係，読み取りのみ，本文・辞書・gitを変更しない，日本語，根拠のファイルと行），最初に `AGENTS.md` と対象章・依存箇所を読むこと，唯一の権威は `detail/main-detail.tex` から読まれる本文であること，過去ログを根拠に採択を変更しないこと，問いと現行案・代替案・最小例・制約，成果物の形（支持／修正／撤回と理由，最強の反論，批判が致命的／修正可能／好みのどれか，決定を覆しうる観察，残る未決点）．
2. 実行：`.claude/scripts/consult.sh codex $0 detail/discussion/<今日>/$0-codex-prompt.md`．応答は `$0-codex-response.md`．
3. 応答を本文と照合し，一往復（必要なら二往復）で暫定採択する．本文へ日付付き「暫定」で入れる．
4. 作者には結果と反対理由だけを短く報告する．

## チェックリスト
- [ ] プロンプトに問い・現行案・代替案・最小例・制約・成果物の形がある．
- [ ] プロンプトと応答が日付ログに保存されている．
- [ ] 採択の根拠が codex の同意ではなく，本文・例・帰結で書かれている．
- [ ] 根の変更・趣味判断を採択していない．
