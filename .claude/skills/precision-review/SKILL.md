## 入力
- $0：対象の章ファイルまたは範囲（例 `detail/chapters/s-side/endurants.tex`）．
- $1：過去レビューのパス（任意）．
- 権威は `detail/main-detail.tex` から読まれる有効本文だけ．`\iffalse` 内や過去ログの記述は，有効本文の問題と区別する．

今日: !`date +%F` ／ ログ置き場: !`bash ${CLAUDE_PROJECT_DIR}/.claude/scripts/newlog.sh` ／ 基準コミット: !`git -C ${CLAUDE_PROJECT_DIR} rev-parse --short HEAD`

## 禁止事項
- これはレビューだけの依頼である．本文・辞書・レビュー以外のファイルを変更しない．提案を本文へ採択しない．
- 形式化の都合で用法や例の目的を変えない（口語の用法を形式化して文語を作る方向）．
- 検証例を増やすためだけに本文の増補を提案しない．
- 過去ログやAIの合意を「決まったこと」として扱わない．

## 手順
1. **対象と目的の確認**．対象ファイル全体と依存箇所（定義の参照元・参照先，実践編の用例，辞書の署名）を読む．$1 があれば照合し，未読・スキップした範囲を記す．各説明・例が何を示すためにあるかを確認する．既存の議論がありそうな論点は `investigator` へ論点ごとに分担し，現在の定義・過去の提案と反論・未調査範囲を出典付きで返させる．その間に依存しない検討を進める．
2. **精読と検証**．`/reader-questions` の型で疑問を立て，本文の定義・具体例・辞書・実装に当たる．問題があるという判断も検証対象とする：別の箇所に答えがないか，自分が余分な条件を要求していないかを確かめる．既存の例を展開して検算し，足りない検証は先に作業ログ（`<対象名>-verification.txt` など）で行う．検算・辞書照合は `verifier` へ委ねてよい．
3. **レビューの作成**．`detail/discussion/<今日>/precision-review-<対象名>.md` を書く．冒頭に対象・行数・基準コミット・ブランチ・検証範囲（読んだ依存先，読まなかった範囲，原典照合していない主張）．各項目は固定番号（E01…）を持ち，本文へのリンクと行番号，疑問，根拠，修正案，対応状態（初期値「未解決」），優先度を含む．項目を「誤り」「定義不足・要検討」「簡潔さ・構成」「検証不足」に分ける．修正案を出せない疑問も残す．
4. **完成度の評価**．誤りの少なさ・文章の簡潔さ・話題の網羅性を5段階（5が最高）で評価し，短い根拠を添える．点数は検討の代わりにしない．数量はアラビア数字．本文への記入を依頼された場合だけ，対象節の `leftwavybox` 環境へ置く．

報告：レビューのパス，項目数（分類別），評価点，作者の裁定が要る項目（根の変更・趣味判断）を短く．S側の要議論項目の暫定採択は `/review-respond` の段階で行う．

## チェックリスト
- [ ] `git status` で本文・辞書に変更がない．
- [ ] 冒頭に基準コミット・検証範囲・未読範囲がある．
- [ ] 各項目に番号・行番号・疑問・根拠・修正案・対応状態・優先度がある．
- [ ] 「問題がある」という判断自体を，別箇所の答えと余分な条件の有無で検証した．
- [ ] 評価点に根拠が付き，アラビア数字である．
