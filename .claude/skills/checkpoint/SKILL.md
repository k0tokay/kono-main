## 入力
- $ARGUMENTS：コミットメッセージの要旨（任意）．
- 現在の差分: !`git status --short | head -40`

## 禁止事項
- push しない．
- 無関係な領域の変更を一つのコミットに混ぜない（precommit フックが混在を警告する）．
- 品質ガードを通さずにコミットしない（フックが拒否する）．
- `git add` と `git commit` を同じコマンド行に書かない（フックがステージ前に検査する）．
- 作者が依頼した場合と，検証済みの区切り以外でコミットしない．

## 手順
1. `git diff` で変更を読み，本文と依存先・辞書の整合を検査する．定義を変えたなら依存する説明・例文・形式化・辞書が同じ変更に含まれているか．対象外の不整合は報告に明記する．
2. `.claude/scripts/quality-gate.sh` を通す（変更領域に応じてビルド・lint・辞書検証・テスト・ハーネス検査）．不合格なら直して再実行．参照を確定させたいときは `--full`．
3. 領域ごとに `git add` する．
4. 別コマンドで `git commit`．一行目に日本語の要旨，本文で何を決めたか（暫定なら日付付き）を続ける．
5. 報告：コミットハッシュ，品質ガードの結果，残る未解決．
6. 使ったスキルがあれば `/retro` を勧める．

## チェックリスト
- [ ] 品質ガードのスタンプがコミット対象より新しい．
- [ ] コミットが一つの領域に収まっている．
- [ ] 要旨に，何を決めたか（暫定の有無と日付）がある．
