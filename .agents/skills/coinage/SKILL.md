## 入力
- $ARGUMENTS：造語したい概念．各概念に意味・親（辞書ID）・署名（arguments の型）が要る．足りなければ先にこのセッションで確定する．
- 規則：`detail/chapters/p-side/word-creation.tex`（経路・優先順位・手順（意味先行））と音韻章（結合表，F型の既定位置）．

今日: !`date +%F`

## 禁止事項
- 別エージェントに造語を任せない（2026-09-30 作者判断：文脈を持った主担当が直接作る方が良い）．
- 略記にすぎない記号に一律に新語を与えない．既存の長形で足りるものと，独立した語が必要なものを区別する．
- 造語で意味条件の穴を埋めたことにしない．未定義の意味条件は本文側の未決として残す．
- 語形の採否を AI で決めない．趣味判断は作者の裁定範囲．推す候補を示すのはよいが，採択として扱わない．
- 辞書 JSON を直接編集しない．登録はパッチで，作者の判定の後に行う．
- 既存の語を分割した断片（suy-，liim- など）や音列を，作者が形態素と認めていないのに形態素として使わない．使うなら「形態素と認めるか」を作者への問いとして明示する．

## 手順
1. **既存の形態素を調べる**：`npm run --silent dict -- search`，`form`，関連語の `contents`（語源）．作者が認めた形態素（例：構造 lek／leka，結ぶ lem／leme／lemae，公理 klamf）を優先する．
2. **判定**：各概念について「新しい語根が要る（基本語）」「形態素合成で足りる（分類語・技術語）」を理由付きで決める．合成に要る形態素が辞書にないとき（演算，測度など），その形態素を先に造る．
3. **候補を作る**：概念ごとに3個，経路を2種以上混ぜる（造語章「経路」）．分類語は形態素合成を主にし，日常語は印象造語を主にする（「優先順位」）．綴りは長ライムで書く．
4. **検査**：`python3 kono-phonology/scripts/check_candidates.py [--parent ID] 候補...`．✗（結合表・子音4連続）は捨てる．△（既存語と距離≤1）は差し替える．F既定位置で長音化が要る候補は長ライムに直す．
5. **候補表**を `detail/discussion/<今日>/coinage-<主題>.md` に書く：綴り｜音節｜経路｜根拠（場面・由来・合成の内訳）｜検査結果｜気になる点．新しく使う形態素と，作者に問う形態素の判断を末尾に列挙する．
6. **作者へ報告**：概念ごとの候補，推す理由，形態素の問いを短く出して止まる．
7. **採択後**：辞書登録をパッチ（add／set_fields）で `apply --write`．〈〉の仮項目なら entry を置き換え，`要造語` タグを外す．本文に語形が出ていれば同じ変更で直す．判定の理由は造語章の「観察と未解決点」に戻す．
