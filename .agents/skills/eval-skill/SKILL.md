---
name: eval-skill
description: スキルの読み合わせ評価．新しいスキルや大きく変えたスキルを，過去の類似タスクの記録と突き合わせ，手順の抜け・曖昧さ・過剰を列挙する．既定は実行しない読み合わせ（安価）．--run で別文脈の実行まで行う（高価．判断が本体の作業には向かない）．「スキルを評価して」「読み合わせて」で使う．
argument-hint: <スキル名 | --all> [--run] [過去タスクのログパス...]
allowed-tools: Read, Grep, Glob, Write, Bash(ls *), Bash(git log*), Bash(git diff*), Bash(python3 *), Agent
---

## 入力
- $0：評価するスキル名．`--all` なら全スキルの棚卸し（各スキルにつき軽く 1 件）．
- $1 以降：ドライランに使う過去タスクの記録（`detail/discussion/<日付>/…`）．指定がなければ，スキルの主題に合う記録を日付ログから 2 件選ぶ（例：`precision-review` なら過去の `precision-review-*.md` とその作者コメント）．
- 前版との比較が要る場合は `git log -p -- .Codex/skills/$0/SKILL.md` で前版を得る．

今日: !`date +%F` ／ スキル一覧: !`ls "${CLAUDE_PROJECT_DIR}/.Codex/skills"`

## 禁止事項
- ドライランで本文・辞書・レビューを変更しない．成果物は `.Codex/dryrun/` と作業用の一時ファイルだけ．
- 実績（人間が確認した過去の成果）を正解として扱い，スキルの出力が実績と食い違う理由を「実績が間違い」で片付けない．
- 評価を印象で書かない．手順の行番号と記録の箇所を対応づけて書く．
- `--run` を既定にしない．判断が本体の作業（レビュー，制作）では実行評価の PASS/FAIL は意味が薄く，費用だけ大きい．

## 手順
1. `.Codex/skills/$0/SKILL.md` を読み，入力・禁止事項・手順・チェックリストを把握する．
2. **読み合わせ（既定）**．過去タスクの記録（レビュー，作者コメント，反映記録）を読み，手順を一行ずつ当てる：その行はこの記録で実行されたか，実行されていたら結果はどう変わったか，記録にある作業で手順にないものは何か，手順にあって記録に痕跡がない行は何か（不要の候補）．
3. **実行（`--run` のときだけ）**．別文脈のサブエージェントにスキル本文と当時の入力だけを渡して実行させる．当時の成果物や作者コメントは渡さない．本文の版は当時の基準コミットに合わせる．出力を実績と比べる．費用（トークン・時間）を記録する．
4. 結果を `.Codex/dryrun/<今日>-$0.md` に書く：対象スキルの版，使った記録，手順の抜け・曖昧さ・過剰の一覧（手順番号付き），改善案（スキル本文の差分として）．3 軸（再現性・改善度・副作用）は `--run` のときだけ PASS/FAIL で付ける．
5. 改善案があれば `/improve-skill $0` を勧める．

## チェックリスト
- [ ] 手順の各行について，記録での痕跡の有無が書かれている．
- [ ] `--run` のときは別文脈で，当時の成果物を見せずに行い，費用を記録した．
- [ ] FAIL の改善案がスキル本文の差分として書かれている．
- [ ] 本文・辞書・レビューに変更がない（`git status` で確認）．
