## 入力
- $0：振り返る対象のスキル名（`.Codex/skills/$0/SKILL.md`）．複数なら主なもの．
- $1：主題（対象章や作業名）．
- この会話でのタスクの経過（依頼，中間結果，作者コメント，最終成果）．
- 未反映の過去の Try：`.Codex/retro/*.md`，`.Codex/dryrun/*.md` のうち `→ 反映` の付いていないもの．

今日: !`date +%F` ／ 未反映: !`grep -L '→ 反映' "${CLAUDE_PROJECT_DIR}"/.Codex/retro/*.md "${CLAUDE_PROJECT_DIR}"/.Codex/dryrun/*.md 2>/dev/null | grep -v README`

## 禁止事項
- 成果物の自賛や一般論を書かない．手順のどの行が効いたか，どの行が守られなかったかを書く．
- Problem を書いて Try を書かないままにしない．Try はスキル本文への具体的な変更（追加・削除・順序の入れ替え）として書く．
- 理論の内容（採否や本文の是非）をここで裁かない．それは日付ログと本文の仕事．
- スキルの差分を作者の了承なしに当てない（スキルは制度そのもの）．
- 手順を増やすだけにしない．足した行と同じ数だけ，冗長になった行を削れないか見る．

## 手順
1. `.Codex/skills/$0/SKILL.md` を読み，手順・禁止事項・チェックリストを一行ずつ，今回の経過と突き合わせる．
2. **Keep**：機能した手順・禁止事項．次回も残す理由を一行で．
3. **Problem**：守られなかった手順，足りなかった入力，冗長だった手順，フックが検知できなかった問題．作者コメントで指摘された点を必ず含める．
4. **Try**：Problem ごとに一つ．(a) スキル本文の変更，(b) フック・スクリプトへの機械化，(c) 見送り（理由）のどれかに割り当てる．人間の注意に頼る対策より機械判定を優先する．守られなかった禁止事項は，該当する手順の**直前**に再掲する（末尾では無視される）．
5. `.Codex/retro/<今日>-$0-$1.md` に `# <スキル> / <主題>`，`## 経過`（3〜5行），`## Keep`，`## Problem`，`## Try`（対応する Problem 番号と (a)(b)(c)）を書く．
6. (a)(b) の差分案を作者に短く示して止まる．
7. 了承後に当てる：(a) は標準形式（入力／禁止事項／手順／チェックリスト）を保って本文へ．`.agents/skills/` のコピーも `.Codex/`→`.Codex/` の置き換えで同じにする．(b) はスクリプトとテストを書き，フックか `formal-check.sh` に組み込む．
8. 反映元の各 Try に `→ 反映: <要旨>` か `→ 見送り: <理由>` を追記し，formal-check を通して `/checkpoint`．

## チェックリスト
- [ ] Keep/Problem/Try が手順・禁止事項・チェックリストの行に対応づいている．
- [ ] 作者コメントの指摘が Problem に含まれている．
- [ ] 差分は作者の了承後に当て，反映元に `→ 反映` を追記した．
- [ ] 標準形式の4節がそろっている（formal-check の harness-skills）．
